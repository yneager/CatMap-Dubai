## 4. Order of work (data shape first)

Do it in this order, so the web app never writes something the new rules refuse:

1. **Shared fields and algorithms** (Phases 4–5): `geoCells` and `searchTerms` on every post and cat write, with the
   exact Android algorithms. Port the test vectors: `app/src/test/java/com/catmap/dubai/data/GeohashTest.kt`,

   in `web/tests/` (copy the vectors into the web tests; don't read cat-server at runtime).
2. **Rules-related writes** (Phases 2, 6, 9): the private alert-area centre, `rateLimited` stamps, alerts one write per
   person, AI-job delete only after the answer or the 15 s timeout, exactly the Android model fields on every
   collection the Phase 9 caps cover.
3. **Safe reading** (Phase 2): type-safe `*FromDoc` functions; one malformed document never breaks a screen.
4. **Cost** (Phases 3–5): map by area with the saved copy, cursor paging (never offsets), Firestore search with
   `searchTerms`, nearby and by-id queries, the smaller live windows (inbox 30, chat 50, updates 30), 30-day photo
   cache. A failed-precondition (index still building) must fall back the way Android does.
5. **Privacy** (Phases 6–7): logout and account deletion leave nothing of the account in the browser; alert routes
   from the fixed list only; thumbnails first.
6. **App Check, monitoring only** (Phase 9): see the `WEB_TODO.txt` item and `docs/security/APP_CHECK.md`. Read the
   site key from `VITE_RECAPTCHA_SITE_KEY` (add it to `.env.example` empty, never a real value); no key = App Check
   off. Never enforce from code, and never initialise it in the emulator build.
7. **The "missed in earlier rounds" parity items** (share post/cat, directions, breed traits, admin match analytics,
   chat "View profile", "Add my location", adoption-requests entry, small hints, `docs/done/web-parity-unused-strings.txt`).

* **Alerts:** never one batch for several recipients (one refusal would cancel all).
* **No new dependencies** unless needed for App Check (`firebase/app-check` is part of the existing `firebase`

* Read `firebase.json` (hosting) and `web/vite.config.ts` (VitePWA). Check the Content-Security-Policy still allows
  exactly what the app needs after App Check (reCAPTCHA Enterprise: `https://www.google.com`,

  sign-in or the map; say what you decided.
* The service worker caches only the app's own files: no Firestore, Auth or photo responses, and no runtime cache
  that could carry one account's data to the next. Add a unit or e2e check for this.
