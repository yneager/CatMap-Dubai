## 4. Install gate: CatMap Web runs only as an installed app

### Detecting "installed"

Installed means one of:
* `matchMedia('(display-mode: standalone)').matches` or `matchMedia('(display-mode: fullscreen)').matches`;
* `navigator.standalone === true` (iOS).

Put this in one helper, for example `web/src/platform/install.ts`, and use it everywhere. Remove the old
`ios`/`web_install_hint` banner in `App.tsx`; the gate replaces it.

### When not installed

Show a full-screen **InstallGate** instead of the app, before the login screen. This matters on iPhone: Safari and
the home-screen app have **separate storage**, so signing in inside Safari would be wasted.
* The gate uses the app's own look: logo, title, theme, light/dark, English/Arabic and RTL.
* It never mounts Firebase Auth or Firestore listeners. It must cost no Firestore reads.

What the gate shows depends on the browser:

* **iPhone/iPad, Safari:**
  * Step-by-step "Add to Home Screen" instructions with the iOS Share icon drawn inline (our own SVG; no Apple
    artwork).
  * Then "Open CatMap from your Home Screen."
  * Point an animated arrow toward the Share button: bottom bar on iPhone, top on iPad.
  * On iOS 26+, mention that "Open as Web App" must stay on.
* **iPhone, other browsers** (Chrome, Edge, Firefox; iOS 16.4+): the same instructions for their share menu.
* **iPhone, in-app browsers** (Instagram, WhatsApp, Facebook, TikTok, Gmail, and similar webviews that can't install):
  * Say "Open this page in Safari to install CatMap."
  * Add a "Copy link" button (it exists already: `web_link_copied` / `web_copy_link_failed`).
  * Detect them by user agent and by the missing Share-to-home-screen path; when unsure, show the Safari instructions.
* **Android, Chrome or Edge:**
  * Capture `beforeinstallprompt` early, in `main.tsx` before React renders, so it isn't missed.
  * Show a big **Install CatMap** button that calls `prompt()`.
  * If the event never fires, show the "⋮ menu → Install app / Add to Home screen" instructions.
  * After `appinstalled`, show "Installed. Open CatMap from your home screen."
* **Desktop:**
  * Show "CatMap is made for your phone" with a QR code of the current URL (the `qrcode` dependency exists) to open
    it on an iPhone.
  * If `beforeinstallprompt` fired (Chrome or Edge desktop), also offer "Install on this computer". That way the
    owner can still demo it on a laptop as an installed app.

### Keep the link

Deep links (for example a post link shared on WhatsApp) still show the gate.
* Keep the path in the manifest's `start_url` logic: a link opened after install on Android is captured by the
  installed app.
* On iPhone the home-screen app starts at `start_url` (`/map`). That's acceptable; mention it in the report.

### Escape hatches (needed for development and tests; never for production users)

* `vite --mode emulators` (dev) and `--mode emulators` builds turn the gate **off** by default.
* `VITE_INSTALL_GATE=on` turns it back on for gate tests. A normal production build always has it **on**, and the
  build must fail if a production build sets `VITE_INSTALL_GATE=off`. Do it the same way `VITE_USE_EMULATORS` is
  checked in `vite.config.ts`.
* No query-string or localStorage bypass in production.

### Manifest and iOS meta

Review `vite.config.ts` (VitePWA manifest) and `index.html`:
* `display: standalone`, plus `display_override: ["standalone"]`;
* `orientation: portrait`;
* a stable `id: "/"`;
* `start_url: "/map"`, `scope: "/"`;
* light and dark `theme-color` metas, using `media="(prefers-color-scheme: dark)"`;
* `apple-mobile-web-app-capable` and `mobile-web-app-capable`;
* `apple-mobile-web-app-status-bar-style` set to `black-translucent`, with every top bar padded by
  `env(safe-area-inset-top)` (check the notch and Dynamic Island in WebKit screenshots at 393×852 and 430×932);
* iOS splash images (`apple-touch-startup-image`) for current iPhone sizes, light and dark, generated by a script
  from the existing icon. If that grows the precache by more than about 1.5 MB, generate a few common sizes and
  explain.

## 5. Remove web-page behaviour

Do this in one place where possible: `theme.css` plus one small module, for example `web/src/platform/appFeel.ts`,
started in `main.tsx`. Some of it exists already (`overscroll-behavior: none`, `touch-action: manipulation`). Audit
it and complete it.

### No page zoom

* Viewport: `width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover`.
* iOS ignores `user-scalable=no`, so also:
  * `preventDefault()` on `gesturestart`, `gesturechange` and `gestureend` on `document`;
  * `touch-action: manipulation` on interactive elements, to stop double-tap zoom;
  * `-webkit-text-size-adjust: 100%`.
* **Focus zoom:** every `input`, `textarea` and `select` needs a computed font-size of at least 16 px (iOS zooms
  into smaller ones). Keep the visual look by adjusting padding if needed.
* **Desktop:** block Ctrl/Cmd + wheel, and Ctrl/Cmd + `+`/`-`/`0`.
* **Keep these working:**
  * pinch and double-tap zoom **inside** the MapLibre map;
  * zoom inside the photo viewer (`ui/cats/PhotoViewer.tsx`).

  Test both on WebKit with touch emulation after the change.

### No pull-to-refresh and no rubber band

* `overscroll-behavior: none` on `html` and `body`.
* The app shell is a fixed full-height frame (`position: fixed; inset: 0` or `100dvh`). It must not scroll as a
  page; each screen scrolls inside its own container, with `overscroll-behavior: contain`.
* Android Chrome's pull-to-refresh and iOS bounce must both be gone, while scrolling inside lists still works.

### Replacing reload

Nothing must need a reload:
* Firestore data is live.
* The service-worker update stays an in-app banner (`web_update_available` / `web_reload`).
* Make sure Settings → About has "Check for updates", which calls the service worker `update()`. Android has the
  same entry.

### No selection, callouts or browser menus

* `user-select: none` and `-webkit-user-select: none` app-wide.
* Allow selection where Android allows it:
  * `input`, `textarea`, `[contenteditable]`;
  * any text Android lets you copy (check the chat bubble long-press in Android `ui/messages/`; mirror it).
* `-webkit-touch-callout: none` on images and links.
* `draggable="false"` on images.
* `-webkit-tap-highlight-color: transparent`.
* Block `contextmenu`, except in editable fields.

### Other website leftovers

* Hover styles only inside `@media (hover: hover) and (pointer: fine)`.
* No visible scrollbars.
* No focus rings on tap; keep them for the keyboard with `:focus-visible`.
* No text cursor on non-editable text: use `cursor: default` on the app shell.

### Navigation like an app

* Every screen keeps its on-screen back button: the iOS home-screen app has no browser back button.
* Add an **edge swipe-back** gesture, iOS style:
  * it starts within 20 px of the leading edge, from the left in English and the right in Arabic;
  * it follows the finger and calls `navigate(-1)`;
  * it's disabled on root tabs and while a map or photo viewer has the touch.
* Android's hardware Back must keep working through history.

### Links

* External links (phone, WhatsApp, email, maps, GitHub) open outside the app.
* Same-origin links must stay inside the standalone window. Never use `target=_blank` for internal routes.

### Title

`document.title` stays "CatMap Dubai". Don't change it per page; it shows in the iOS app switcher.

## 6. Map regression (fixed by Claude; add the test)

**Bug:** on the live site, the map was blank on phones; the owner saw it on Android Chrome.

**Cause:**
* `CommunityMap.tsx` imports `maplibre-gl/dist/maplibre-gl.css`. In a production build that CSS is a separate chunk,
  `CommunityMap-*.css`, loaded **after** `index-*.css`.
* MapLibre's `.maplibregl-map { position: relative }` has the same specificity as our `.map-canvas { position:
  absolute; inset: 0 }`, so it won. The map container ended up 0 px tall.
* Dev mode injects CSS in a different order, so the e2e suite (which ran against dev) never saw it.

**Fix (already in `web/src/ui/theme/theme.css`):** the selector is now `.community-map > .map-canvas`. Claude
verified it in a `--mode emulators` production build at phone size: the canvas is 652 px tall and the tiles and
markers draw.

**Your tasks:**
1. Add a Playwright test that runs against a **production** build (`vite build --mode emulators` plus `vite preview`,
   like `pwa.spec.ts` does). On `/map` it checks:
   * the `.map-canvas` height is above 300 px;
   * `.maplibregl-canvas` has a non-zero size;
   * the style loads.

   Do the same for the compact map in the post editor's "Where & when" step.
2. Audit the other lazily loaded CSS (any `import '*.css'` outside `main.tsx`) for the same order problem. Make sure
   app rules that must beat library rules use higher specificity, not load order.
3. Make the e2e suite run against a production preview build by default, or at least add a preview-build project to
   `playwright.config.ts` that CI-style runs include, so the next bug of this kind is caught.
